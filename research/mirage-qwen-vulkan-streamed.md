# MIRAGE 003 · Registered non-mapped Vulkan loading

The original Vulkan startup loaded the model in mmap mode and exceeded the 640 MiB process working-set guard before serving any request. The stopped attempt is preserved as actual startup telemetry with zero model responses. The pinned runtime source can stage non-mapped uploads in four bounded buffers or a reused buffer sized around a single tensor where asynchronous uploads are unavailable. Use official `--load-mode none` to select that route. Require logs to confirm the changed loader and full offload.

Every hardware limit, model hash, prompt, sampler setting, scoring rule, capability threshold and ECHO decision rule from the original frozen Vulkan protocol remains in force. This configuration uses a distinct durable journal and any prior requests are excluded. The load option changes the weight-loading mechanism and leaves the decoded checkpoint unchanged. Empirical cross-model results still compare a Vulkan Qwen configuration with the archived CPU SmolLM2 configuration.
