# SYNAPSE workspace rules

Read PROJECT_STATE.md, inspect Git status and recent commits, then resume the next unfinished task. Preserve other repositories. Record decisions, unresolved limits and evidence in the state register.

Label synthetic, empirical, exploratory and published evidence explicitly. Cite primary sources with exact locators where possible. Freeze confirmatory protocols before opening their results. Record failures and material protocol changes. Use one synthetic task as the unit of inference for paired ECHO analyses. Never infer subjective consciousness from behaviour or label an AI review as human peer review.

Use the shared pure engine for both the Node runner and the browser. Keep numerical changes behind reference tests. Keep versioned configuration, validation and provenance beside the runner. Use local artifacts instead of telemetry or an API for the first slice. No personal data, credentials, externally executed code or paid resources. Use public portfolio source only after checking reuse terms.

Use Node 24.12.0 and npm 11.6.2. Run npm test, npm run reference, npm run verify, and npm run build before a release. Use npm run pilot and npm run experiment to regenerate outputs. Keep branches reviewable. A computed output, its checked reproduction and limits must accompany any quantitative claim.

Use static, safe DOM rendering, bounded controls and relative links. Record browser and accessibility checks. Track public deployment and independent review with actual evidence.

For Phase II, preserve v1 archival inputs and outputs byte for byte. Run python scripts/reference_echo2.py and node scripts/echo2.mjs verify alongside v1 checks. Distinguish finite exchangeability from latent mixture families and exact bounds from simulation sampling intervals.
