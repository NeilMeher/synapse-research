# Contributing

Start with the workspace rules and state register. Keep a change small enough that a reviewer can rerun its model and explain the outcome. Include the protocol, configuration, model code, actual outputs, limitations and test commands. Label evidence applicability and disclose generated work.

Use separate branches for implementation and external review. Keep scientific protocol changes traceable, maintain prior artifacts and classify data-dependent changes as exploratory. Review attribution and redistribution rights before importing outside code or data. Use the [independent review package](research/external-review.md) for scientific or accessibility findings.
